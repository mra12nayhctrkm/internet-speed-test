# internet-speed-test

Консольная утилита на Node.js, которая замеряет скорость скачивания: делает **10 последовательных запросов** к заданному адресу, дожидается полного ответа на каждый, считает среднее время запроса, общий объём данных и скорость.

Дополнительно показывает медиану, p95 и TTFB, умеет прогревочные запросы, повторы при сбоях, прогресс-бар и вывод в JSON.

Работает **без runtime-зависимостей**: встроенный `fetch`, `node:test`, `node:util/parseArgs`. Dev-зависимости (TypeScript, ESLint, Prettier) нужны только для проверок качества.

## Требования

Node.js **20+** (`node -v`). Для запуска `npm install` не нужен.

## Запуск

```bash
npm start -- "https://speed.cloudflare.com/__down?bytes=5000000"
```

или напрямую:

```bash
node bin/speedtest.js <url> [options]
```

| Опция                | По умолчанию | Описание                                                                                   |
| -------------------- | ------------ | ------------------------------------------------------------------------------------------ |
| `-n, --requests <n>` | `10`         | количество замеряемых запросов                                                             |
| `-w, --warmup <n>`   | `0`          | прогревочные запросы перед замером, в результат не входят                                  |
| `-r, --retries <n>`  | `0`          | повторы запроса при сетевой ошибке, таймауте, 408/425/429/5xx; задержка 0.5 с, 1 с, 2 с, … |
| `-t, --timeout <s>`  | `30`         | таймаут одной попытки в секундах, включая скачивание тела                                  |
| `--json`             |              | результат в JSON (для скриптов и CI)                                                       |
| `-h, --help`         |              | справка                                                                                    |
| `-V, --version`      |              | версия                                                                                     |

Установка как команды (необязательно): `npm link`, затем `speedtest <url>`.

### Пример вывода

```
Target: https://speed.cloudflare.com/__down?bytes=5000000
  # 1          5.00 MB   6574.3 ms  TTFB 6393.3 ms
  # 2          5.00 MB    228.9 ms  TTFB   48.4 ms
  ...
  #10          5.00 MB    213.1 ms  TTFB   35.5 ms

Requests:       10
Total data:     50.00 MB
Average time:   889.5 ms per request
Time, ms:       min 209.4 · median 247.9 · p95 3785.3 · max 6574.3
TTFB, ms:       min 32.9 · median 43.5 · p95 3612.2 · max 6393.3
Download speed: 44.97 Mbit/s (5.62 MB/s)
```

Это реальный прогон: первый запрос ждал ответа 6.4 с (холодные DNS и TLS), и одно это занизило среднюю скорость втрое. Медиана и p95 сразу показывают выброс, а `--warmup 1` убирает его из замера:

```
$ node bin/speedtest.js "https://speed.cloudflare.com/__down?bytes=5000000" -n 3 -w 1
...
Download speed: 143.73 Mbit/s (17.97 MB/s)
```

На интерактивном терминале во время скачивания в stderr рисуется строка прогресса (`#3  1.20 MB / 5.00 MB (24%)`). При выводе в pipe и в режиме `--json` её нет.

## Единицы измерения

- **Скорость** — мегабиты в секунду, **Мбит/с (Mbit/s)**, как её указывают провайдеры. В скобках дублируется в **МБ/с (MB/s)**.
- 1 Mbit = 1 000 000 бит, 1 MB = 1 000 000 байт (десятичные, не MiB). 1 MB/s = 8 Mbit/s.
- **Время** — миллисекунды (ms), **объём** — мегабайты (MB).
- В JSON: `bytesPerSecond` (байт/с), `mbitPerSecond` (Мбит/с), время в мс (`*Ms`), объём в байтах.

## Как считается

- **Время запроса** — от отправки до получения **последнего байта тела** (DNS, TLS, ожидание и скачивание). Часы монотонные: `performance.now()`.
- **TTFB** — от отправки до получения заголовков ответа. Помогает отличить медленный сервер от медленного канала.
- **Скорость** = `общий объём / суммарное время запросов`. Это взвешенная величина, а не среднее арифметическое скоростей отдельных запросов. Паузы между запросами не учитываются.
- **p95** считается линейной интерполяцией между рангами (как в NumPy и Excel `PERCENTILE.INC`).
- **Байты.** Запрос отправляется с `Accept-Encoding: identity`, поэтому считаются байты в том виде, в каком лежат на сервере, без gzip/br. Тело читается потоком и не копится в памяти, поэтому подходят и большие файлы.
- **Повторы.** Учитывается время только успешной попытки: неудачные попытки и паузы между ними ничего не говорят о скорости канала.
- **Ошибки.** Редиректы выполняются автоматически. Если запрос так и не удался после всех повторов, запуск прерывается с сообщением о том, какой запрос упал и почему: частичный замер вводил бы в заблуждение.

Результат зависит от кэша и CDN: к запросу добавлен `Cache-Control: no-cache`, но сервер вправе его проигнорировать.

## Коды выхода

`0` — успех, `1` — ошибка замера (сеть, таймаут, HTTP-статус), `2` — неверные аргументы или URL.

## Разработка

```bash
npm install
npm run check   # lint + format:check + typecheck + test
```

| Скрипт                  | Что делает                                           |
| ----------------------- | ---------------------------------------------------- |
| `npm test`              | тесты (`node:test`)                                  |
| `npm run test:coverage` | тесты с отчётом покрытия                             |
| `npm run typecheck`     | строгая проверка типов JS по JSDoc (`tsc --checkJs`) |
| `npm run lint`          | ESLint                                               |
| `npm run format`        | Prettier                                             |

Код написан на чистом JS с JSDoc-типами и проверяется TypeScript в strict-режиме. Так получаются типобезопасность и запуск без шага сборки.

CI (GitHub Actions) прогоняет все проверки на Node 20, 22, 24 (Ubuntu) и Node 24 (macOS).

### Тесты

Тесты поднимают локальный HTTP-сервер и не ходят в интернет. Покрытие строк 100%. Что проверяется:

- ровно 10 запросов, строго последовательно (сервер следит за одновременными соединениями);
- ожидание полного тела (сервер отдаёт его частями с паузой);
- точность формул, TTFB и статистики (с подменёнными часами);
- повторы с экспоненциальной задержкой; 4xx не повторяются; учитывается время только успешной попытки;
- прогрев, прогресс (с `Content-Length` и без), отправляемые заголовки;
- таймауты: зависший сервер, тело, оборванное на середине, повтор после таймаута;
- ошибки: non-2xx, отказ в соединении, редиректы, пустое тело, неверный ввод;
- CLI: вывод, `--json`, прогресс только на TTY, коды выхода на реальном бинарнике.
